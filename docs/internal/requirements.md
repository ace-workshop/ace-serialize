### 1.2 活路径、死路径及现状骨架

**保留语义来源**：String/Array/Collection/Builtin/Nullable/Type formatter → 生成器短集合 API `WriteArray/WriteList/WriteDictionary` → `Assemble`。短集合 `u16 count` 家族确实是活代码，但 Rust 将计数改为 u32。builtin root unmanaged array 的 raw-u32 路径也活着，Rust 将其统一而不是遗漏它（F §3–4；P13）。

**不复刻**：`Write/ReadArrayField`、`Write/ReadListField`、`Write/ReadDictionaryField` 六个仓内零入边入口，以及只由其调用的六个 `*Value`；`SerializeUniversal/DeserializeUniversal` 入口、旧 `Write/ReadUnmanagedNumberField` 链、`ValueHeader`、16 字节 `ReferenceHeader`。这里的「死」限定仓内静态调用审计，不声称外部 DLL 没有调用（F §2、§5）。

**C# 活路径真实骨架，必须与 Rust 新约定区分**（D §3.1–3.7，E §1–4）：

```text
[i32 main 长度][main][i32 assist 长度][assist]
main   = 记录堆：每条 {i32 InstId, i32 Size} 8 字节头 + body，可嵌套
assist = 槽位流：按 (i32 Depth, i32 Tag) 定位，常规槽另有 8 字节 payload
         数值直接入槽，引用放 id；Nullable 小类型是现有缺陷例外
缺省/null 字段不写槽；tag 缺口 + peek 回退识别缺席，不靠字段总计数
集合为一条记录，含 count + 元素；builtin root unmanaged array 有 raw 特例
默认再叠 8 字节分组 bitmask 压缩，C# 有 ff [N-1] [8*N 原始字节] 逃逸段
```

Rust 保留双区与缺席识别思路，但 **不与 C# 字节互通**：数值规范扩展、统一 root、u32 count、对象槽范围、数值多态及标准 packed 都是明确差异。Rust 的字段归属按记录槽范围，不能照搬 C# 全流 `(depth, tag)` 定位。

- 读写 C# 历史二进制档、历史迁移、老版/死路径 API 或 header 的兼容。
- 复刻 C# 缺陷行为，包括邻接内存泄漏、错误 Nullable、哈希身份合并、静默越界。
- 跨端序兼容或端序协商：协议固定小端；不得按宿主端序直接拷贝整数。
- 本期性能门槛：现有耗时含进程启动，不用于性能对比。不得把此非目标解释为可无限分配。
- 流式/增量 API；`Mutex<T>` 等跨 FFI 有锁语义容器、`Arc<dyn Trait>` 泛型对象、跨语言共享同一份 `AceValue` 图。
- 自动 C# 反射/程序集装载、Rust 内存布局透传、任意 Rust 类型自动成为稳定 wire 类型。
- 本期 C ABI 的强引用环与 `Weak` 反向边（分别返回既有 `14 CycleUnsupported`／`11 Unsupported`）；共享身份与多态对象自 v0.26 起纳入 C ABI（FR-A00/R32/R33），R07 原口径「C ABI 无共享/无环/无 Weak/无别名/无多态变体判别」已被取代（保留历史，见 §7.3 R07）。Rust API 的对应承诺不变。
- `#[ace(skip, default = <expr>)]`自定义构造表达式；本期skip仅使用字段类型的`Default`。

**C# 剩余能力的等价映射登记（R13；以下按等价映射登记，不按非目标处置）**：`Pinwheel.Toolkits.Guid`（64位）→ 按位可逆映射 `u64`（FR-T08⑤）；任意 unmanaged 自动 fallback（含 decimal 数据）→ 不承诺「未标注类型自动成为 wire 类型」（Rust 无反射，见上方非目标条目），但数据能力保留：由用户结构 + `#[derive(AceSerialize)]` 或手写 impl 表达同一数据（如 `{lo,mid,hi,flags}` 或 `i128+scale`），不是删除 decimal 功能（FR-T08⑥）；`System.Type` 值 → 以显式 `type_key` 字符串（FR-T10）或枚举数值 tag（FR-W07）表达类型标识，不提供运行期类型对象（FR-T10）；运行期替换 formatter → 已记为后续批次的明确范围差异（FR-T10），不是遗漏。

| FR-W10 | Rust main一律平铺记录，无嵌套record，不保留C# root raw特例。除root Option::None外，根槽恒为assist[0]（16B、depth=0/tag=0），不属于任何对象范围。root为引用型（object/string/集合/Rc/Arc/Box/多态enum及Option::Some的引用型）时payload放root record id（从1起，8B零扩展）；≤8B标量root按FR-W12放数值槽，零值也必有根槽。root Option<≤8B标量>::Some(v)直接放数值根槽，不新增primitive record；None无根槽且assist长度0。>8B定宽值root（如Guid、DateTimeOffset）按FR-T12第②支走record：根槽payload放该值record id（8B零扩展），record body写完整定宽字节；root Option<宽值>::Some(v)同理；root Option<宽值>::None无根槽（assist长度0）。因此None为0B assist，Some(0)为16B assist且payload=0。字段省略规则不得吞掉非Option根值 | R01/R13；AC-W01/T02/T08 |
| FR-W11 | wire不加magic、版本字段、checksum或根类型头；调用方须提供正确schema和压缩模式。ABI版本由`ace_abi_version()`查询；schema演进用稳定order/reserved和未知槽跳过。不得声称能从任意字节自动识别格式版本或自动识别raw/packed | P01/P11；AC-A01、AC-W03 |

**数值宽度表（FR-W12）**：所有整数小端；字段槽只从类型自然位值构造8B payload，不读取相邻内存。无符号/正数零扩展，有符号负数符号扩展。bool仅0/1；char为Unicode标量值u32（不是C# UTF-16 code unit）；f32为IEEE754低4B位模式+高4B零，f64为原8B位模式。不规范化NaN；浮点缺省只认全零位模式，-0必须写。自然宽度集合元素分别为bool 1B、i8/u8 1B、i16/u16 2B、i32/u32/f32/char 4B、i64/u64/f64 8B。枚举见FR-T01。（P02/P05/P10/P14；AC-W01、AC-T03）

derive 生成代码在该路径（含身份/引用追踪所需的全部内部状态）仍不得发生堆分配，该状态改由 `scratch` 承载，不得以排除受支持类型的方式达成，手写实现自身分配的边界（①②③）照旧。R15 含义不变（不放宽）：最终完整 wire（raw/packed 分别按各自实际结果）长度恰好等于 `dst` 容量时必须成功，且不得因身份追踪或其它工作空间要求让调用方多预留 `dst` 容量——该工作空间由 `scratch` 承担，不再与 `dst` 竞争。**同一次调用中容量维度的两类条件如何同时适用**：当 `dst` 容量恰好等于最终 wire 长度、但 `scratch` 不足以容纳本次调用所需的身份条目时，返回既有 `1 InvalidArgument`（属调用方提供的参数不足，沿用既有码）；当 `scratch` ### 2.4 C ABI

**FR-A00 本期能力边界（C ABI；v0.26 起按 R32/R33 修订）**：

- **支持**：①**共享身份**——同一对象可被多处引用；编码只写一次 record、其余位置写引用 id；解码时同一 wire id **返回同一个原生节点**（指针身份保留，契约见 R32）。②**多态对象**——`AceValue` 对象带 `type_key`；嵌套对象按**其自身 `type_key`** 查已注册 schema 编码/解码，**不按**父容器的静态字段 schema（契约见 R33）。
- **仍不支持**：①强引用环 → 既有 `14 CycleUnsupported`；②`Weak` 反向边 → 既有 `11 Unsupported`。
- **保留**：不新增 `AceKind` 值；除 R32① 唯一新增的 `ace_value_share` 外，既有函数签名集合不变；Rust API 的对应承诺不变；§8 三项 ABI 细部冻结门的数目不变（C 头冻结范围按 R32/R33 补充，不新增门）。
- **实施顺序**：分两批实现，**先共享（R32）、再多态（R33）**。

**R07 原口径已被 R32/R33 取代（保留历史）**：R07 原文「本期 C ABI 仅树状动态值，无共享/环/Weak/别名/多态变体判别；ABI 扩展属于后续批次而非冻结选项」不再有效；C ABI 的能力边界以本条与 R32/R33 为准。（R32/R33；AC-A01、AC-A05、AC-A06）

**FR-A01 函数族与稳定边界**（U08，P07/P08/P11/P12）：必须导出以下职责；完整C头及细部签名按§8在实现前冻结。D7旧版的`serialize(type_key,in_ptr,in_len,...)`已被父会话撤回，不能透传Rust对象内存。

|---|---|
| `ace_abi_version() -> u32` | 返回固定ABI版本常量，供调用方显式检查；不往wire插版本。常量的发布值在C头冻结 |
| `ace_value_object(type_key)`、`ace_value_*` | Rust分配动态值句柄；种类Null/Bool/I64/U64/F64/Str/Bytes/List/Object。不跨边界暴露Rust Vec/String/TypeId |

**FR-A02 所有权与参数安全**：成功输出移交调用方，失败输出必须为空、不泄漏半成品；buffer free后清零结构，使同一结构体再次free不double-free。每个拥有型value/options句柄只释放一次，借用视图寿命不超过父对象，父修改后的视图失效规则须在C头明确；不承诺任意伪造、悬垂、重复释放非空句柄安全。NULL与len组合、out参数合法性、type_key编码必须校验，但库不能验证任意外部野指针指向可读内存。AC-A02覆盖失败释放与收编配对。

**FR-A03 类型校验**：注册表是schema白名单，type_key是调用方维护的稳定UTF-8字符串，不是Rust类型名。I64/U64向目标整数只许无损范围转换；负数不得转u64。F64→f32只许精确表示，包含±0、±inf及按位NaN规则，不允许静默舍入；f32→f64允许无损加宽。字符串与bytes不隐式互转，其他不匹配TypeMismatch。schema具体宽度决定编码，而不是动态值种类一律8B。（P12；AC-A03）

**FR-A04 线程、重入与panic**：不得依赖全局可变调用缓存；每次调用独立，不同独立value/buffer/options的并行调用和前次失败后的新调用不相互污染。同一AceBuffer/选项及同一可变value图不得并发使用；不承诺跨语言共享同一图。FFI层使用std与catch_unwind兜底，unwind panic转PanicCaught，Rust unwind不得越过C边界；不承诺捕获panic=abort、OOM abort、栈溢出。有效但畸形的字节输入应正常Result错误，而不是靠catch_unwind掩盖解析器panic。（U08，P07；AC-A02、AC-A04）

**FR-A05 稳定C错误码**：0..16闭集顺序固定；以后只能末尾追加（`16 DuplicateKey` 按此追加，R24）。Rust内部Result错误可更细，但必须有完整映射。VersionMismatch用于ABI协商结果，不伪称wire有版本；NotFound是合法查询无项，不是解码截断。

**R32 共享身份的最小契约（v0.26；用户批准，2026-11-20；本条是 C ABI 共享身份的唯一权威位置，FR-A00 只写能力边界）**：

①**唯一新增 C 函数**：`int32_t ace_value_share(const AceValue *value, AceValue **out);`——成功时 `*out` 指向与 `value` **同一个原生节点**、该节点引用计数 +1（返回 `0 Ok`）。失败按三类处置，输出口径与 **FR-A02「失败输出必须为空」**一致：(a)**`out` 无效（`NULL`）**→返回既有 `1 InvalidArgument`，**不访问输出**（无从置空，也不构成 FR-A02 的例外）；(b)**`out` 合法且参数在检查范围内可判定无效**（如 `value == NULL`）→返回既有 `1 InvalidArgument`，**把 `*out` 置空（`NULL`）**，不得留下半成品、不得沿用调用方原值；(c)**任意伪造／悬垂／非本库分配的 `value`**→**不新增任何安全保证**，沿用 FR-A02 的既有边界（不承诺任意伪造、悬垂、重复释放非空句柄安全，不能验证野指针指向可读内存）——**不得**承诺此时返回 `1` 且安全。`out` 合法仅表示库在写前可判定该输出位置可写（同 FR-A02 的 `out` 参数合法性校验），不对外部指针的可读性作额外承诺。**既有 C 函数签名与 `AceKind` 集合一律不变**（不新增 `AceKind` 值）。

②**身份适用范围**：承诺**对象与引用类容器（list / map / str / bytes）**的节点身份（同一 wire 引用 id ↔ 同一原生节点）；**标量与 >8B 宽值 record 不承诺身份**，与 `FR-T12`②「宽值 record 为值语义、不参与引用身份复用」一致——不得据指针相等/不等断言标量或宽值被合并或未被合并。

③**身份范围仅限一次消息／一次 `ace_deserialize`**：同一次 `ace_deserialize` 内同一 wire 引用 id 必须解析为同一个原生节点；**不得跨调用缓存指针身份**；原生节点释放后地址可能被复用，**不得据此推断**跨调用的身份关系。

④**schema 一致性**：同一节点在不同（不兼容）schema 下复用必须返回既有 `13 TypeMismatch`；**不得为规避该错误而写出两条 record**（同一身份在一条消息内不得有两条记录）。

⑤**收编语义（引用计数）**：`ace_object_set` / `ace_list_add` **成功改为「引用 +1」**：子值被父容器引用后**调用方句柄仍有效**（仍可读取、可再次 `ace_value_share`），并**须由调用方自行 `ace_value_free` 减引用**（不得以「已收编」为由省略该次 free）；失败时未收编、引用不加、`child` 仍由调用方拥有（既有条款不变）。C 头中原「成功收编后子句柄失效、归父对象所有、调用方不得再 free」的措辞**随之改写**（C 头属门 A 冻结范围，本轮不改 `include/`）。`ace_value_free` 每调用一次减一次引用，减到 0 才释放节点；每枚句柄只释放一次（重复 free 既禁止不变）。

⑥**强环**：C 侧可构造强环（如 `set` 使对象引用自身或其祖先）；`ace_serialize` 对该图返回既有 `14 CycleUnsupported`，不得挂起、不得栈溢出、不得把部分写入当作成功；`ace_value_free` 对强环**按引用计数语义不保证释放**（环内引用互相持有）——Rust 文档与 C 头**必须明确「调用方不得构造强环」**。`Weak` 反向边在 C ABI 仍不支持，按既有 `11 Unsupported`（同 FR-A00）。

⑦**C# 侧映射责任**：`对象 ↔ AceValue*`（编码方向）与 `AceValue* ↔ 托管对象`（解码方向）**两张映射表由调用方维护**；库只保证原生侧指针身份（同③），**不承诺 C# 托管对象同一性、不提供托管侧映射 API**；同一托管对象重复放入须由调用方自行 `ace_value_share` 同一个 `AceValue*`，否则不构成共享身份。

（R32；FR-A00、FR-T12、FR-A01/A02、AC-A05；错误码 `14`/`11`/`13`/`1` 均沿用既有表、不新增码；取代 R07 的 C ABI 能力口径）

**R33 多态对象（v0.26；用户批准，2026-11-20；本条是 C ABI 多态对象的唯一权威位置）**：

①**类型标识载体**：`AceValue` 对象经 `ace_value_object(type_key, ...)`（FR-A01 既有构造接口）携带其类型标识 `type_key`；`type_key` 是调用方维护的稳定 UTF-8 字符串（FR-A03），不是 Rust 类型名。

②**按自身 `type_key` 分派**：编解码嵌套对象时按**该节点自身的 `type_key`** 查已注册 schema，**不是**按父容器的静态字段 schema——例如 `List<基类>` 的元素按各自 `type_key` 分派到对应派生 schema；`type_key` 未注册 → 既有 `3 UnknownTypeKey`（编码与解码两侧口径相同）。

③**wire 表达沿用既有规则**：wire 上的多态表达沿用既有 Rust 侧多态规则（FR-W07 的 `variant_tag` 与 `type_name` 逃生口），**不得为 C ABI 新造格式、不得新增 wire 概念**；同一 schema 下 C 侧编码的字节须能被 Rust 侧解码、反之亦然。

④**未知变体**：`ace_deserialize` 遇未知变体（判别值不属于该 schema 已注册集合）→ 既有 `4 InvalidTag`（同 FR-W07、BAD-08 语义，不新增码）。

⑤**与共享组合**：身份仍按**节点指针**判定、**不按 `type_key`**——`type_key` 相同且字段值相等的不同节点不得因此合并为同一节点；同一节点被多处引用时仍按 R32 的引用去重。

⑥**无自身 `type_key` 的普通对象体与「同 key 异布局」的歧义（v0.33 增补，用户批准 2026-11-20 选项 A）**：普通对象体（8 字节体）在 wire 上**不携带「值是否自带 `type_key`」的信息**，因此当某位置的 schema 内嵌了 `type_key = K` 的对象，而白名单（FR-A03 的 schema 注册表）又注册了**同名 `K` 但布局不同**的 schema 时，该位置的编码结果无法自解释。规则：**编码时若值本身不带 `type_key`、且白名单中存在与其位置 schema 同 `type_key` 但布局不同的注册项，则返回既有 `13 TypeMismatch`**（fail-closed，不产生歧义 wire、不新增错误码、不改 wire 格式）。以下情形**不受影响**：(a) 位置 schema 未注册同 `type_key`；(b) 注册布局与内嵌布局一致；(c) 值**自带** `type_key`（此时按 R33② 走注册目标，自带 key 且布局不同属正常多态路径）。该规则只影响**原本会产生歧义**的输入，不改变其它成功输入的字节。

（R33；FR-A00、FR-W07、FR-A01/A03、AC-A06；不新增 `AceKind` 值与错误码）

### 2.5 错误、安全与资源

- **FR-E01**：所有面向字节的codec入口返回Result；截断、越界、长度算术溢出、非法bool/char/enum/presence、负长度、非法id、重复id均不得成功、不得静默填零/返None冒充合法缺席。引用body按目标schema校验，不承诺总能检测类型不符（NFR-S02）。完整范围内无可省略字段才是合法缺席，不可省略字段缺席报15；不完整16B尾槽是坏包，二者不可混淆。
- **FR-E02**：读取/分配前检查记录和槽范围；不得信任线上Size做unchecked span，不得先按恶意count分配再验包。引用循环按图规则解析，缺失记录与重复记录定义都报InvalidReference；重复引用同一合法id不是重复定义。
- **FR-E03**：未知字段跳过不绕过外层长度、槽宽、记录边界、输入/raw/展开/record/slot/引用上限检查，但不要求解析未知record body的内部schema。不得把未知字段等价于未知根schema。
- **FR-E04**：所有资源限制可通过选项调节，调高仍受i32/u32格式可表示上限与算术安全约束；编码、解码、解压分配均执行限制。错误不得留下跨调用缓存或不可释放半图。坏包错误类别须可区分，FFI映射见FR-A05。（AC-E01/E02/G01）
- **FR-E05 预算**：输入长度与解包后raw长度各自独立受限，默认各≤64 MiB；packed零补齐最多+7B但不得额外放宽raw预算。`max_decoded_bytes`默认64 MiB，解码中每实际物化一条record一次就累加该record的size字段值一次；同一record被N个普通所有权字段引用即累加N次。不计分配器私有开销、元数据、对齐padding、Vec扩容新旧块、id表/索引结构本身。`max_records`、`max_slots`默认各2^20，分别限制输入main记录数与assist槽数（含根槽）；未知record也计入记录数。任何上述预算超限返回6 ResourceLimit，物化前检查累加溢出与限额。（R04；AC-E02）

### 2.6 可选压缩层

**FR-P01**：生产默认开启，可显式关闭；raw和packed都应完整往返，解码模式由调用选项指定，不自动猜测。此默认与C#生产默认一致，但编码采用标准Cap’n Proto packed，而非C#私有Packer。（U06；`S/LSerializer.cs:41,58–62`；PACK）

**FR-P01 补充——解码侧身份构造闭包数上限 `max_build_nesting`（`Options` 字段，R25，需求所有者裁决，2026-11-19，选项 A；v0.21 按实现既有口径收敛）**：`Options` 新增对外可配置字段 `max_build_nesting`，①默认 **256**；②超限返回**既有资源限制错误码 `6 ResourceLimit`**（不新增错误码）；③它与既有**编解码结构深度限额**（FR-T07 的深度检查，覆盖编码与解码两侧，默认最大深度 256 见 NFR-L01；超限返回既有 `5 DepthExceeded`）、既有**资源限制**是三个不同限额，必须**分别命名、分别文档化**，不得合并表述或互相替代——**编解码结构深度 → `5`**、**身份构造闭包数 `max_build_nesting` → `6`**；两者**语义分开、默认数值相同**（均为 256），但**不得合并成单一参数**；④**计量对象**：**解码规划阶段同时打开的身份构造闭包峰值**——即既有定义「同时打开的身份构造闭包数上限；不计虚根和普通对象/集合深度」（`crates/ace-serialize/src/limits.rs:10–11`），**不计虚根与普通对象/集合嵌套深度**，不是字节长度、也不是 wire 结构深度；**结构嵌套深度由 `max_depth` 约束**（超限返回 `5 DepthExceeded`，编码与解码两侧都适用），两者不是同一限额；⑤**判定点**：解码规划期——规划结束、进入实际构造之前对构造调度峰值与该限额做一次比较，超出即返回 `6 ResourceLimit`（既有实现 `crates/ace-serialize/src/decode/graph.rs:938–940`）；**编码侧不使用该参数**，编码的深度与嵌套一律由 `max_depth` 判定并返回 `5 DepthExceeded`，本条不声称该参数作用于任何编码或查询入口；⑥属对外可配置项，**必须在 Rust 文档与 C 头（随门 A 冻结）发布**，并如实记为与 C# `DepthLimit = 1000`（`S/LSerializeContext.cs:36`）**有意不对齐**（Rust 栈安全优先），不写成待办。本条只确立该限额的存在、名称、默认值、超限错误类别、计量对象、判定点与发布义务，本条不扩张、不改变 FR-T07 与 NFR-L01 的既有语义（两者文字未改）。

**C ABI 的适用范围（v0.34 增补，用户批准 2026-11-21 选项 A）**：`max_build_nesting` 是**Rust 图解码**（`decode_cyclic` 一类）的身份构造闭包峰值上限；**C ABI 的 `ace_deserialize` 不消费该参数**——C ABI 只承诺树/共享 DAG 的动态值（无强环、无 `Weak`），不存在“身份构造闭包峰值”这一概念。`ace_options_set_build_nesting` **接受并保存**该值（默认 256），但其取值**不影响** C ABI 解码结果或错误码；C 侧的结构深度仍由 `max_depth` 约束（超限 `5`）。**头文件注释须与本节一致**（随门 A 重新登记冻结）。不得据此改变 Rust 侧 R25 语义。

出处（观察）：`max_build_nesting` 的唯一生产消费点＝`crates/ace-serialize/src/decode/graph.rs:1060`（`schedule.peak > self.decoder.options().max_build_nesting` → `Error::ResourceLimit`，Rust 图解码路径）；C ABI 解码链路＝`crates/ace-serialize-ffi/src/lib.rs:3574–3584`（`decode_registered`：`Decoder::new` → `DynReader::value` → `finish`，全程不读该字段），`ace_options_set_build_nesting` 仅保存该值（同文件 `1432–1438`）；`include/` 现行头文件尚未出现该名称，故头注释同步登记在门 A。

**FR-P02 标准规则**：输入按8B word；tag在word之前，第i位表示该word第i字节非零，普通tag只紧随各非零字节。`0x00`不写word体，紧跟u8 N表示后续额外全零word数；`00 00`表示一个零word。`0xff`先写当前word的8字节，再跟u8 N表示后续额外原样word数，再写这N个word；不是`ff [N-1] [8*N字节]`。run最大额外255 word，超出拆段。编码器的原样run延续选择遵守PACK，不新造规则。（P09更正版；AC-P01）

**FR-P03 边界**：最后不足8B的raw包须用已初始化零字节补齐，禁止读tail外内存。解包后用M/A计算逻辑末尾，只允许本次补齐产生的0..7个零尾字节；raw模式不接受额外尾字节。解压输出受独立raw长度预算约束，逻辑raw加本次0..7B补齐仍不得超限；缺tag对应数据、缺run计数、缺run body、展开长度溢出/超限全部Result错误。（AC-P01、AC-E01）
